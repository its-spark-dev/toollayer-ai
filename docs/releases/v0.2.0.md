# v0.2.0 — Authenticated snapshots and verified execution boundaries

## Summary

v0.1.0 documented a set of security properties. Some of them were weaker than the prose
described — not because the controls were absent, but because each one answered a slightly
different question from the one the documentation claimed it answered.

This release closes that gap. Every claim now corresponds to a mechanism and a test that would
fail if the mechanism were removed, and the places where the project still relies on trust
rather than proof say so plainly.

## Highlights

**1 · Authenticated deployment snapshots.** Snapshots carry an Ed25519 signature over the
canonical bytes of the document with the `signature` field removed — covering `snapshot_id` and
`snapshot_digest` as well as every connector. The Control Plane signs from configuration; the
Runtime verifies against an explicitly trusted key ring and refuses by default when it cannot.
Keys rotate through the ring, so a rotation does not need every service to change at once.

**2 · Truly bounded streaming execution.** The outbound transport streams the response in
bounded chunks and closes the connection the moment the running total passes the limit.
`Content-Length` is an early-exit hint, never the control.

**3 · Verified caller identity.** A `verified_token` mode accepts a signed compact JWS and
checks signature, issuer, audience and expiry before deriving a subject and roles. Assertion
headers are refused outright in that mode. `/healthz` reports which mode is in force.

**4 · One request, one immutable snapshot.** A turn acquires the snapshot once and threads it
through discovery, selection, authorization and execution. The tool index is a read-only
mapping, so immutability is deep rather than skin-deep.

**5 · Reproducible builds and stronger CI.** `uv.lock` plus a hash-pinned `requirements.lock`,
used by pip, Docker and CI alike. New jobs build the wheel and install it clean, check lockfile
drift, scan dependencies and history, and run CodeQL.

**6 · Docker end-to-end verification.** CI builds every image, brings the topology up on its
health checks, runs the full demonstration through it, and asserts non-root containers, absent
key material, and answering ports.

**7 · A recruiter-facing portfolio page.** A static GitHub Pages site built from the existing
captures and visual language, for a reader who will not clone the repository.

## Why this release matters

Four distinctions do the work here, and each one was previously blurred.

**A content digest is not a producer signature.** A digest answers *are these the same bytes* —
content addressing, ETag semantics, corruption detection. It authenticates nobody, because
computing SHA-256 requires no secret: an attacker who can rewrite a payload rewrites its digest
with it. The threat model previously named a network attacker who *modifies* traffic and
offered self-digest recomputation as the mitigation. A signature answers *did a holder of this
key produce these bytes*, and that is the claim that survives the attacker in question.

**Asserted identity is not verified identity.** Reading a role from a header and enforcing it is
a trust boundary. It is a reasonable one behind a gateway that has already authenticated the
user, and it is not authentication. The two are now separate named modes, and a deployment
cannot be in the weaker one without saying so.

**Truncating a result is not bounding memory.** Reading a body in full and then slicing it caps
what the runtime processes. It does not cap what the runtime receives, which is the property
that matters when the upstream is hostile or broken.

**Checking source is not checking a distributable system.** Lint, types and tests all passed
against a source tree while the wheel packaging, both Dockerfiles and the Compose topology went
unbuilt by any job. Those are what someone actually runs.

## Compatibility and migration

The contract version moves **1.0.0 → 1.1.0**. `signature` is optional, so a 0.1.0 document
still validates and still parses. The snapshot schema is closed, so a 1.0.0 consumer refuses a
*signed* document — which is what the minor bump makes explicit rather than leaving as an
opaque schema violation.

An existing unsigned snapshot is **refused** under the default
`TOOLLAYER_SNAPSHOT_VERIFICATION=required` with `snapshot_signature_invalid`. It loads only
under an explicit `disabled`, which is logged and reported by `/healthz`. Published snapshots
are immutable and cannot gain a signature retroactively; republish once signing is configured.

Upgrading requires configuring signing material, trusting the public half at each runtime,
choosing an identity mode, republishing snapshots, and reinstalling from the lockfile. The
console container's internal port moved from 80 to 8080; the published host port is unchanged.
`make demo` and `make demo-docker` need none of this — both generate an ephemeral pair per run.

Step-by-step instructions are in [`CHANGELOG.md`](../../CHANGELOG.md#migration-from-010).

## Remaining limitations

Unchanged by this release, and stated rather than implied:

- Static admin and service tokens between the two services. Snapshot *signing* keys rotate;
  these do not.
- Caller identity is asserted rather than verified in the default demo topology.
- No external identity-provider integration. The verification seam is real; populating it from
  a live JWKS endpoint is not implemented.
- No TLS or mTLS in the local Compose topology. Signatures authenticate the artifact, not the
  transport.
- No secret manager. Secrets come from the environment, with no encryption at rest.
- Revocation is polling at the refresh interval, not push.
- A DNS time-of-check-to-time-of-use gap remains between address checking and connection. No
  pinned-IP protection is claimed.
- No rate limiting or quotas.
- The audit trail is ordinary mutable database rows — a record, not tamper-evident evidence.
- No metrics or tracing.
- Single-tenant.
- No OAuth flow or end-user credential broker. Connectors carry an opaque `auth_profile_ref`
  and no secret.
- One tool per request. No chaining, no conversation memory.
- No hosted model provider. The default is a deterministic offline stand-in behind a real
  interface.

This is a portfolio project, not a production system.

## Portfolio context

The work in this release is mostly about the distance between a claim and a mechanism:
noticing that a hash and a signature answer different questions, that a bounded result and a
bounded read are different properties, and that a green test suite over a source tree says
nothing about the artifact someone installs. Closing each gap meant changing the contract, the
implementation, the tests and the prose together, and keeping the parts that remain
trust-based clearly labelled as such.
