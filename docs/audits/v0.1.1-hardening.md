# v0.1.1 — Security hardening audit

Records what was found, what was changed, and what was verified. Every number below was
derived by running the command shown, not read from an earlier document.

The v0.1.0 audit is at [`v0.1.0-pre-publication.md`](v0.1.0-pre-publication.md). Its counts and
statuses describe that version and were correct then; they are not updated here.

---

## 1. Findings

Two claims in the v0.1.0 documentation described protections the code did not provide. Both are
fixed in implementation, tests, and documentation. Three further defects were found while
verifying them.

### 1.1 A content digest was described as defeating an active attacker

**What the code did.** A deployment snapshot embedded a SHA-256 digest over its own canonical
serialization, and the runtime recomputed it before accepting the payload.

**What that protects against.** Corruption in transit or storage, and a payload edited without
its digest being updated.

**What it does not.** An attacker who can rewrite the response body can also recompute the
digest, because computing SHA-256 requires no secret. The document remains internally
consistent and every check passes.

**What the documentation claimed.** `docs/threat-model.md` §5.11 was titled "Substituting a
snapshot in transit", listed a network attacker who "sees or **modifies** traffic between
services", and gave self-digest recomputation as the mitigation. `docs/runtime.md` said "TLS
proves who sent the bytes, not that the bytes are the artifact that was published", which
implies the digest supplies what TLS does not. `docs/architecture.md` called the artifact
"self-verifying".

**Correction.** Snapshots now carry an Ed25519 signature over the canonical bytes of the whole
document with the `signature` field removed — which therefore covers `snapshot_id` and
`snapshot_digest` as well as every connector. The Control Plane signs with a private key from
its environment; the runtime verifies against an explicitly configured trusted key ring and
refuses by default when it cannot. The digest is unchanged and keeps its own job: content
addressing, ETag semantics, reproducibility, corruption detection.

**Test that would have caught it.**
`tests/security/test_snapshot_authenticity.py::TestTampering::test_content_and_digest_both_replaced_is_still_refused`
constructs the forgery, asserts it is digest-consistent, and asserts the load is refused.

### 1.2 A response bound was described as non-buffering

**What the code did.** `HttpxTransport.send` called `client.request(...)` and then sliced
`response.content[: limit + 1]`. `response.content` has already read the entire body into
memory; the slice bounded only what was passed onward.

**What the test proved.** `test_an_oversized_response_is_refused_rather_than_buffered`
substituted a transport that returned an already-materialized `b"x" * (limit + 1)`. It could
not observe buffering, because buffering was what the fixture did. The real transport had no
test coverage at all.

**Correction.** The transport now streams: `client.stream(...)`, `iter_bytes()` in 64 KiB
chunks, and the response closed the moment the running total reaches the limit. A truthful
oversized `Content-Length` short-circuits before any body is read; a missing or understated one
changes nothing, because the running total decides. Retries are explicitly disabled;
`follow_redirects=False` and `trust_env=False` are unchanged.

**Test.** `tests/integration/test_streaming_response_limits.py` runs the real transport against
a real `ThreadingHTTPServer` on loopback. The server records how many bytes it managed to write;
`test_the_client_stops_consuming_after_the_limit_is_crossed` asserts that count stayed far below
what an endless stream would have produced. The old test was renamed to
`test_an_oversized_response_is_refused_by_the_executor`, which is what it checks.

### 1.3 One request could span two snapshot revisions

`Orchestrator.handle` called `store.ensure_fresh()` and then `discover()`, which called
`ensure_fresh()` again. A refresh landing between them let one turn discover tools from one
revision and execute against another, with a policy nobody had evaluated as a whole.
`LoadedSnapshot` was also a frozen dataclass wrapping a mutable `dict`, so its immutability
stopped at the outermost object.

**Correction.** The snapshot is acquired once and threaded through discovery, selection,
resolution, authorization, execution and the trace. `discover_in(snapshot, caller)` takes the
snapshot; the public discovery endpoint still acquires its own. The tool index is a
`MappingProxyType`.

**Tests.** `tests/integration/test_snapshot_consistency.py` — `TestOneRequestOneRevision` forces
a refresh from inside the provider hook, between discovery and execution, and asserts the turn
does not notice; `TestDeepImmutability` asserts the index cannot be written, cleared, popped or
replaced.

### 1.4 A malformed port produced an unhandled exception

`urllib.parse.SplitResult.port` raises `ValueError` lazily, at the point of access rather than
at parse time. `DestinationPolicy.check` guarded `urlsplit()` but read `.port` and `.hostname`
outside that guard, so `https://api.example.org:99999/v1` raised from a line that does not look
like parsing — reaching the unhandled-exception path and a 500 instead of a policy refusal.

**Correction.** All authority parsing is centralized in one function where every failing
attribute access is guarded; every failure becomes `destination_not_allowed`. IPv4-mapped IPv6
addresses are unwrapped before the address-family checks, so `::ffff:127.0.0.1` is judged as
loopback rather than as an unremarkable IPv6 address. Trailing dots are stripped so
`api.example.org.` cannot be a second spelling of an allowlisted origin.

**Tests.** `TestMalformedDestinations` in `tests/unit/test_policy_engine.py` — 14 malformed
inputs, the IPv4-mapped cases, default-port normalization, uppercase hosts, literal IPv4 and
IPv6 destinations, and an assertion that a malformed URL never triggers a DNS lookup.

### 1.5 Schema format validation was silently inactive

Found while verifying the above. `toollayer_contracts.validation` passes
`format_checker=FormatChecker()`, but `jsonschema` skips the `date-time` format entirely unless
`rfc3339-validator` is installed — and it was not a declared dependency. With format checking
actually enabled, published connector documents failed validation: timestamps read back from
SQLite come out naive, so `_rfc3339` produced `2026-08-06T01:53:37` with no UTC offset.

So "the document is validated against the normative schema" quietly meant "except for formats",
and a document this service accepted was one a conforming consumer would have rejected.

**Correction.** `_rfc3339` treats a naive datetime as UTC, and `rfc3339-validator` is now a
declared dependency so the format keyword is enforced rather than skipped.

**Test.** `test_every_published_timestamp_is_a_valid_rfc_3339_date_time` asserts the format
directly, so the check no longer depends on which optional packages happen to be present.

## 3. What changed

**Contract.** `signature` added to the deployment-snapshot schema and to `DeploymentSnapshot`.
The digest exclusion list is now a shared constant so producer and consumer cannot drift.
`snapshot_signature_invalid` added as a distinct error code — "these bytes are damaged" and
"these bytes are not ours" say different things to an operator.

**Control Plane.** Signs snapshots when a key is configured; refuses to start on half a signing
configuration or unusable key material. `/healthz` reports the signing mode and key id.
Snapshot summaries carry `signed`, `signing_key_id` and `signature_algorithm`.

**Runtime.** Verification modes (`required` by default, `disabled` by name only), a trusted key
ring supporting rotation, a streaming transport, one-snapshot-per-request, a read-only tool
index, and a caller-authentication boundary with `asserted_header` and `verified_token` modes.
`/healthz` reports every relaxation in one place; `/readyz` reports which key authenticated the
snapshot being served.

**Policy engine.** Centralized authority parsing, IPv4-mapped address unwrapping, trailing-dot
normalization.

**Build.** `uv.lock` plus a hash-pinned `requirements.lock`, base images pinned to patch
versions, `cryptography` and `rfc3339-validator` added, `vite` and `vitest` upgraded. The
console container runs as the unprivileged `nginx` user on port 8080.

**CI.** New `package`, `docker`, `lockfiles` and `supply-chain` jobs; a separate CodeQL
workflow; Dependabot for uv, npm, actions and Docker; `ruff format --check`, which `make lint`
ran but CI did not.

**Documentation.** Every claim listed in §1 corrected. `check_docs.py` derives test counts and
compares them against every document, verifies the pytest exit code before reading a count, and
refuses five retired claims by pattern so they cannot return in a rewrite.

## 4. Accepted limitations

Unchanged by this pass, and stated rather than implied.

| Limitation | Disposition |
|---|---|
| Static admin and service tokens | Accepted. Snapshot *signing* keys rotate; these do not |
| Asserted caller identity in the demo topology | Partially improved — a verified-token seam exists and is tested; the demo runs asserted, and says so |
| Identity-provider integration (JWKS, refresh, revocation) | Future work. Building it becomes an identity product |
| TLS / mTLS | Accepted. Signatures authenticate the artifact, not the transport |
| Secret management | Accepted. Environment variables; no vault, no encryption at rest |
| Immediate revocation | Accepted. Polling at the refresh interval, not push |
| DNS TOCTOU | Accepted and explicit. Addresses are checked before the request; the transport resolves again when it connects. No pinned-IP protection is claimed |
| Rate limiting and quotas | Accepted |
| Tamper-evident audit logging | Accepted. Ordinary mutable rows — a record, not evidence |
| Metrics and tracing | Accepted |
| Multi-tenancy | Future work. A tenant column without isolation would be a claim, not a feature |
| Horizontal snapshot distribution | Future work |
| Real OAuth and end-user credential brokerage | Future work. Connectors carry an opaque `auth_profile_ref` and no secret |
| Multi-step tool chaining | Future work. A loop is the structure whose absence the injection tests rely on |
| Conversation memory | Out of scope. The runtime is not a chatbot product |
| Real hosted model provider | Out of scope. A hosted provider ends the offline guarantee |
